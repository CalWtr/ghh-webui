# ghh-webui

Browser UI for [GHH](https://github.com/CalWtr/ghh). It talks to the GHH `api` port and listens on the public `bell` port for live updates. There is no build step and no server of its own.

- `GHH.dc.html`: the UI, a Claude Design component (template plus `Component` logic).
- `ghh-client.js`: request envelope, snapshot loader, API-to-UI adapters, bell listener. Exposes `window.GHH`.
- `support.js`: generated by Claude Design. Do not edit. React and Babel load from unpkg at runtime, so the page needs internet.

## Run

Serve the directory over http. `file://` sends `Origin: null`, which Relative rejects.

```sh
python3 -m http.server 8080
# open http://localhost:8080/GHH.dc.html
```

Start Relative with the UI origin allowed, and the GHH model running:

```sh
RELATIVE_ALLOWED_ORIGINS=http://localhost:8080 ...
```

Then open Settings and set:

- **API endpoint**: `localhost:2704/api/models/<model-id>/ports/api`. Relative routes by model UUID, not by name. The default is the id of the model in `/home/caleb/repositories/ghh`.
- **Bearer token**: a `ghh_…` token for a GHH user (`npm run bootstrap -- --admin-name <name>` in the ghh repo prints the first admin token).

Endpoint and token are stored in this browser's `localStorage`.

## Live updates

The UI opens `ws://<host>/api/models/<model-id>/ports/bell`. A frame carries only a timestamp; the UI refetches through the authenticated API on every frame and on every (re)connect. If the socket drops, it retries with backoff up to 15 s. The header shows `live`, `connecting…` or `offline, retrying`.

## Behavior that follows from the API

- **Tokens**: a user has one token. Issuing a new one replaces the old. Issuing your own switches this browser to the new token; copy it, it is not shown again. The token list in Settings is a local record only.
- **Webhooks**: subscriptions cannot be edited. Save creates the new subscription and deletes the old one, so a fresh secret is needed (leave the field blank to generate one; it is shown once). Delivery status is not exposed by the API.
- **Inbox**: needs an `internal` subscription. The Inbox view offers to create one for tasks assigned to you.
- **Assignee**: a planned task can be assigned, an active task can be unclaimed or handed off, and only project members are offered.
- **User type** (human or agent) is fixed at creation.
- **Delegation** view approximates "tasks I created that are assigned to someone else".
- Task edits are versioned (`if_match`). A `version_conflict` triggers a reload.
